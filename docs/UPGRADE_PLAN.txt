# 鲸鱼娘 V2 多模态智能体升级计划书

> 基于 llmenv + LocalMind + Agent Embodiment 三位一体架构
> 日期：2026-07-23

---

## 一、技术对标分析

| 鲸鱼娘 V2 需求 | 对标项目 | 核心能力 | 适配方案 |
|:---|:---|:---|:---|
| **上下文/身份管理** | [llmenv](https://github.com/RohanKaranjee/llmenv) v2.0 | identity/profile/project/pins 分层 YAML 上下文 | 升级 `core/config/` TOML 系统 + `persona.toml` |
| **本地知识引擎** | [LocalMind](https://github.com/ixxrllg/localmind) | BM25 + Embeddings 混合检索、MCP Server、import graph | 升级 `plugins/knowledge_base` 插件 |
| **虚拟形象具身化** | [live2d-embodied-avatar](https://github.com/devnanix/live2d-embodied-avatar) | 6种 Agentic States、声明式 JSON 动画、WebSocket 同步 | 升级 `plugins/static_stand` + 新增 `plugins/live2d_embodiment` |
| **AI 绘画/图像处理** | ComfyUI | 自定义工作流、文生图/图生图/编辑 | 新建 `plugins/comfyui_processor` |
| **多平台适配** | NachoBot 架构 | Core + Adapter 模式、插件系统 | 新建 `adapters/` 占位 |

## 二、六大模块详细设计

### 模块 1：llmenv 式上下文引擎

**对标功能：**
- `llmenv identity` → 用户身份和偏好持久化
- `llmenv init` → 项目级别上下文初始化
- `llmenv scan` → 自动检测技术栈和环境
- `llmenv profile` → 按任务切换上下文（build/review/debug/refactor）
- `llmenv pin` → 持久化规则和纠正

**适配设计：**

```
config/
├── identity.toml          # 全局身份（跨项目持久化）
│   ├── [user]             # 用户名/偏好/城市/笔记
│   ├── [preferences]      # 代码风格、语言偏好、回复风格
│   └── [pins]             # 全局规则（"永远不要用英文回复"）
├── persona.toml            # 人设（已存在，需升级）
│   └── [profiles]         # 新增多模式支持
│       ├── [profiles.chat]      # 日常聊天模式
│       ├── [profiles.coding]    # 编程辅助模式
│       ├── [profiles.review]    # 代码审查模式
│       └── [profiles.teaching]  # 教学模式
└── plugins.toml            # 插件上下文
```

**新增组件：`core/context_engine.py`**
- 启动时自动扫描项目结构（技术栈检测）
- 运行时根据用户消息自动切换 profile
- Pins 系统：将用户纠正持久化为规则注入 system prompt
- 优先级链：全局 pins > profile rules > persona defaults

### 模块 2：LocalMind 式本地知识引擎

**对标功能：**
- 行感知分块（line-aware chunker）
- BM25 倒排索引 + Embeddings 混合检索
- import/link 关系图谱
- MCP Server 暴露工具
- SQLite 本地存储，零网络依赖

**适配设计：**

```
plugins/knowledge_base/     # 现有插件全面升级
├── manifest.json            # 新增工具定义
├── main.py                  # 保留 ChromaDB 向量检索
├── bm25_indexer.py          # 新增 BM25 分词+倒排索引
├── hybrid_search.py         # 新增 BM25×Embedding 混合检索
├── relation_graph.py        # 新增 文件依赖关系图
└── mcp_server.py            # 新增 MCP Server（stdio 协议）
```

**新增工具：**

| 工具名 | 功能 | 对标 LocalMind |
|:---|:---|:---|
| `kb_search` | 混合检索（BM25 + 向量 + 重排序） | `search_code` |
| `kb_ask` | 带引用的问答 | `ask_codebase` |
| `kb_related` | 查找依赖关系 | `find_related_files` |
| `kb_explain` | 解释文件/行范围 | `explain_file` |
| `kb_status` | 索引统计 | `index_status` |
| `kb_reindex` | 增量/全量重建 | `reindex` |
| `kb_mcp` | 启动 MCP Server | — |

**技术栈：**
- BM25：使用 `rank_bm25` Python 库，分词用 jieba（中文优化）
- 混合检索：BM25 score × 0.3 + Vector cosine × 0.7（可配置权重）
- MCP Server：FastMCP Python 库，stdio 协议
- 存储：ChromaDB（向量）+ SQLite（BM25 倒排表 + 关系图）

### 模块 3：Agent Embodiment（Live2D 具身化）

**对标功能：**
- 6 种 Agentic States：idle / thinking / working / responding / error / surprise
- 声明式 JSON 动画参数（Static + Drift）
- WebSocket 状态同步
- Live2D Cubism SDK 驱动

**适配设计：**

```
plugins/live2d_embodiment/   # 新增插件
├── manifest.json
├── main.py                  # 插件入口
├── state_manager.py         # 状态机（idle/thinking/working/responding/error/surprise）
├── ws_bridge.py             # WebSocket 服务端（前端状态推送）
├── states/                  # 状态 JSON 定义（可运行时热加载）
│   ├── manifest.json
│   ├── idle.json
│   ├── thinking.json
│   ├── working.json
│   ├── responding.json
│   ├── error.json
│   └── surprise.json
└── webui/                   # Live2D 前端（独立 HTML，嵌入 Gradio iframe）
    ├── index.html
    ├── live2d_app.ts        # TypeScript → 编译为 JS
    ├── Core/                # Cubism SDK Core
    ├── Framework/           # Cubism SDK Framework
    └── models/              # 鲸鱼娘 Live2D 模型
```

**状态触发协议：**

```
Brain 事件                     → 化身状态
─────────────────────────────────────────
收到用户消息                    → thinking
分发工具调用                    → working
流式回复开始                    → responding
回复完成/无工具调用              → idle
API 异常/工具执行错误            → error
收到服务端推送                   → surprise
```

**与现有 Gradio 的集成方式：**
- Gradio 页面右侧面板嵌入 iframe 显示 Live2D 前端
- WebSocket 服务端随插件启动，监听独立端口（`9873`）
- `core/message_bus.py` 的 `MESSAGE_RECEIVED`/`MESSAGE_SEND`/`TOOL_BEFORE_EXECUTE` 事件自动触发状态切换
- 无需修改 Gradio UI 代码，通过事件总线解耦

**Live2D 模型准备：**
- 短期：使用 Niziiro Mao 示例模型测试（已有 MIT 许可）
- 中期：使用 `static_stand/stand.png` 立绘配合简单动画过渡
- 长期：定制鲸鱼娘 Live2D 模型（需要 Cubism Editor 5）

### 模块 4：ComfyUI 图像处理器

**功能：**
- 文生图（txt2img）：根据描述生成图片
- 图生图（img2img）：基于上传图片变体
- 图像编辑（inpaint/outpaint）：局部重绘/扩展
- 工作流管理：预设工作流模板 + 用户自定义

**适配设计：**

```
plugins/comfyui_processor/   # 升级现有 image_processor 骨架
├── manifest.json
├── main.py                  # 插件入口
├── comfyui_client.py        # ComfyUI WebSocket API 客户端
├── workflow_manager.py      # 工作流模板管理
├── image_handler.py         # 图像上传/下载/预览
├── workflows/               # 工作流模板
│   ├── txt2img.json         # 文生图
│   ├── img2img.json         # 图生图
│   ├── inpaint.json         # 局部重绘
│   └── upscale.json         # 超分
└── generated/               # 生成图片输出目录
```

**工具定义：**

| 工具名 | 功能 |
|:---|:---|
| `image_generate` | 文生图（prompt + 负面提示词 + 尺寸 + 步数） |
| `image_transform` | 图生图/编辑（输入图片路径 + 提示词 + 强度） |
| `image_workflows` | 列出可用工作流 |
| `image_workflow_run` | 运行指定工作流 |
| `image_status` | 查看 ComfyUI 连接状态和生成进度 |

**ComfyUI 集成要点：**
- 通信协议：WebSocket（ComfyUI 原生支持 `ws://127.0.0.1:8188/ws`）
- 进度反馈：通过 WS 消息实时显示生成进度（yield status 事件）
- 工作流模板：JSON 文件存放预设工作流，运行时替换 prompt/seed 参数
- 超时控制：`config/plugins.toml` 中配置 `generation_timeout`

## 四、技术风险与缓解

| 风险 | 影响 | 缓解措施 |
|:---|:---|:---|
| Live2D SDK 需手动下载 | Phase 3 前置依赖 | Phase 3 可先用纯 CSS 动画过渡方案替代，Live2D 作为 Phase 3.5 |
| ComfyUI 需独立部署 | Phase 5 前置依赖 | 先实现 API 客户端 + mock 模式测试，后续接入真实服务 |
| BM25 + ChromaDB 双索引维护 | 存储翻倍、重建变慢 | 增量索引 + 后台异步重建 |
| MCP Server 协议兼容 | IDE 版本差异 | 严格遵循 MCP 规范，提供多种连接方式配置 |
